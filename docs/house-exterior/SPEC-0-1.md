# «Дом снаружи» — техническая спецификация этапов 0–1

Ветка: `house-exterior` (от `ux-overhaul`). Дата: 2026-11-24.
Цель всего раздела: обход дома с iPhone → точный 3D-макет дома и участка → правки → смета.
Этот документ — только этапы **0** (крыша по фото) и **1** (скан → «слепок»). Этапы 2–5 — отдельными документами.

---

## 0. Принципы

1. **У каждого размера метка достоверности**: `measured` (LiDAR/замер, ±1–3 см на Pro), `photo` (геометрия по фото, ±3–10 %), `assumption` (не видно — типовое значение или оценка ИИ). В интерфейсе: зелёная / жёлтая / серая точка + подпись «измерено / по фото / предположение».
2. **Сервер (1 CPU / 2 ГБ) ничего тяжёлого не считает**: принимает пакет, хранит, отдаёт GPU-обработчику, раздаёт результат.
3. **Тяжёлое — на арендуемом GPU с посекундной оплатой**, обработчик запускается на один скан и гасится.
4. **Позиции камер берём из ARKit** (без классического SfM/COLMAP): быстрее и масштаб метрический с первого кадра.
5. Деньги: ИИ ≈ $0.03–0.06 за распознавание крыши; GPU ≈ $0.3–0.6 за скан. Цель себестоимости — 120–230 ₽ за объект.

## Этап 0 — крыша по 3–5 фото (сделано в этой ветке)

**Задача:** проверить, насколько ИИ + геометрия угадывают крышу до того, как строить сканер.

### Как работает
1. Gemini 4 Hydrogen (`google/gemini-4-hydrogen`, $1.5 / $7.5 за 1 млн токенов) получает 3–5 фото и возвращает:
   тип крыши, покрытие, цвет, детали (трубы, слуховые окна, водостоки, снегозадержатели…, у каждой `seen` — видно или предположение),
   и **ключевые точки торцевой стены** на каждом фото: 4 угла стены (у земли и у карниза) + конёк, плюс верх/низ двери.
2. **Геометрию считает код, не ИИ** (`server/src/roof.js`):
   по 4 углам стены строится гомография «фото → плоскость стены в метрах». Это снимает перспективу (ракурс не обязан быть прямым).
   Точка конька переносится в метры → высота конька и уклон каждого ската.
   - Даны ширина торца **и** высота карниза (замер или LiDAR) → размеры `photo`, точность ограничена только точностью точек.
   - Дан один размер → второй по пропорциям стены (нужен почти фронтальный снимок).
   - Нет размеров → масштаб по двери (≈2,05 м) → `assumption`. Уклон от масштаба не зависит — он всегда `photo`.
3. Ответ сводится в итог с метками; что не видно (задние скаты, ендовы) — списком `hidden`; `advice` — что доснять.

### Интерфейсы
- Скрипт: `node server/scripts/roof-test.mjs фото1.jpg … [--width 8.2] [--eave 3.1] [--json out.json]`
- API: `POST /v1/ai/house/roof` `{ photos:[base64 jpeg ×1–6], known:{gableWidth, eaveHeight, ridgeHeight}, notes }` → итог (см. `combine()` в roof.js). Заголовки как у остальных `/v1/ai/*` (X-Install-ID, X-App-Token).
- Тесты геометрии: `server/test/roof.test.js` (синтетический дом снят с ракурсом → уклон 36,9°, конёк 6,00 м точно).

### Пробный прогон (общедоступное фото дома из Википедии)
2 фото → «двускатная, керамическая черепица», уклон 58,8° по фото, конёк ≈10,9 м (масштаб по двери — предположение). **$0.029.**

### Критерий прохождения этапа 0
На 3+ реальных домах пользователя: тип крыши верен; уклон в пределах ±5° при известных размерах; высота конька ±0,3 м при известных ширине торца и высоте карниза.

## Этап 1 — «Скан дома» → слепок

### 1.1 Экраны приложения

**A. Вход.** Карточка «Дом снаружи» (вкладка «Дизайн», рядом с «Скан комнаты») → экран-интро:
что получится, 4 совета (светлое время без резких теней; обойти дом по кругу в 4–8 м от стен; два круга — «ближний» и «дальний» с поднятой камерой для крыши; 5–10 минут), какой у iPhone режим точности:
- **Pro с LiDAR** — «точность до сантиметров»;
- **без LiDAR** — «точность ±2–5 %: после обхода измерьте рулеткой одну стену» (контрольный размер).

**B. Обход (живая камера ARKit).**
- Сверху: **кольцо покрытия** — 36 секторов по 10° вокруг дома, у каждого 2 яруса (стены / крыша). Сектор закрашивается, когда в нём есть резкий ключевой кадр нужного яруса. Посередине — процент.
- Под кольцом — **одна подсказка за раз** (приоритет сверху вниз):
  1. «Мало света / мало деталей» (трекинг ARKit limited),
  2. «Медленнее» (угловая скорость > 60°/с или смаз),
  3. «Отойдите — дом не помещается» (медиана глубины < 3 м) / «Подойдите ближе» (> 20 м),
  4. «Поднимите камеру — снимите крышу / фронтон» (в текущем секторе нет кадра верхнего яруса),
  5. «Идите дальше по кругу →» (текущий сектор закрыт),
  6. «Осталось: сторона справа» (крупная незакрытая дуга).
- Снизу: счётчик кадров и объёма, кнопки «Пауза» и «Готово». «Готово» активна от 60 % покрытия (раньше — с предупреждением).
- Вибро-отклик при закрытии сектора.
- Защита: термо-состояние `.serious` → снижаем частоту кадров; память > 1,2 ГБ на диске → предупреждение.

**C. Контрольный размер (без LiDAR обязательно, с LiDAR — по желанию).** «Измерьте рулеткой длину любой стены» → ввод + выбор стены тапом по превью.

**D. Отправка.** «Упаковываем…» → «Загружаем 34 / 96 МБ» (докачка; можно свернуть приложение — фоновая загрузка). → «Скан на обработке, ~15–30 мин. Пришлём уведомление».

**E. Результат (этап 1 — «слепок»).** 3D-сетка дома (RealityKit, вращение/масштаб), размеры по фасадам с метками достоверности, крыша (тип, уклон, конёк — этап 0, но уже по измеренным стенам). Редактирование — этап 2.

### 1.2 Что записываем при обходе

`ARWorldTrackingConfiguration`: `worldAlignment = .gravity`, `frameSemantics = [.sceneDepth, .smoothedSceneDepth]` при LiDAR, `sceneReconstruction = .mesh` при LiDAR (живой меш — запасной вариант и превью), видео-формат максимальный 4:3 (1920×1440).

**Ключевой кадр** берётся, если одновременно:
- трекинг `normal`;
- от прошлого ключевого кадра сдвиг ≥ 0,35 м **или** поворот ≥ 8°;
- угловая скорость < 60°/с (иначе смаз);
- не чаще 3 кадров в секунду.
Ожидаемо 250–450 кадров на дом.

**Для каждого кадра:** JPEG 1920×1440 q 0,8 (≈350 КБ); глубина 256×192 Float16 (≈98 КБ) + уверенность глубины UInt8 (≈49 КБ) — только LiDAR; поза камеры 4×4 (камера→мир, ARKit), внутренние параметры камеры (fx, fy, cx, cy для размера JPEG), время, экспозиция, состояние трекинга, ярус (стены/крыша по наклону камеры).

**Объём:** 350 кадров ≈ 120 МБ (без LiDAR ≈ 70 МБ). На 1 400 МБ ресурсов телефона — пишется сразу на диск, в памяти не копится.

### 1.3 Формат пакета скана (`scan.zip`, версия 1)

```
manifest.json
frames/000001.jpg …           ключевые кадры
depth/000001.f16              256×192 Float16, метры (LiDAR)
conf/000001.u8                256×192 UInt8 0/1/2 (low/med/high)
mesh/arkit.obj                живой меш ARKit (LiDAR), мировые координаты
```

`manifest.json`:
```json
{
  "format": "smetapro-house-scan", "version": 1, "kind": "house",
  "createdAt": "2026-11-24T12:00:00Z",
  "device": "iPhone17,1", "lidar": true, "ios": "26.1",
  "image": { "width": 1920, "height": 1440 },
  "depth": { "width": 256, "height": 192, "format": "f16", "units": "m" },
  "world": { "alignment": "gravity", "up": [0,1,0], "units": "m", "headingDeg": 132.5, "location": { "lat": 43.6, "lon": 39.7, "accuracy": 12 } },
  "center": [1.2, 0.0, -6.3],
  "coverage": { "sectors": 36, "walls": 0.86, "roof": 0.62 },
  "control": [{ "kind": "wall_length", "meters": 9.42, "frame": 120, "note": "рулетка" }],
  "frames": [
    { "i": 1, "t": 12.533, "image": "frames/000001.jpg", "depth": "depth/000001.f16", "conf": "conf/000001.u8",
      "pose": [16 чисел, column-major, камера→мир], "K": [fx, fy, cx, cy],
      "tracking": "normal", "exposure": 0.008, "tier": "wall" }
  ]
}
```
Камера в позе — как в ARKit: x вправо, y вверх, смотрит вдоль −z. Координаты мира — метры, ось y вверх (гравитация).
GPS и компас (`headingDeg`) — только для тени/солнца (этап 4); без разрешения на геолокацию поля нет.

### 1.4 API сервера (сделано: приём; обработка — после выбора GPU)

| Метод | Путь | Что делает |
|---|---|---|
| POST | `/v1/ai/house/roof` | этап 0 (см. выше) |
| POST | `/v1/ai/house/scans` | `{bytes, sha256, manifest:{frames, device, lidar, kind}}` → `{id, parts, partBytes: 8 МБ, received:[]}` |
| PUT | `/v1/ai/house/scans/{id}/parts/{n}` | сырые байты части n (порядок любой, повтор безопасен) |
| GET | `/v1/ai/house/scans/{id}` | статус: `uploading` → `queued` → `processing` (progress 0..1, message) → `ready` (result) / `failed` |
| POST | `/v1/ai/house/scans/{id}/complete` | склейка частей, проверка SHA-256, постановка в очередь |
| (этап 1b) | `/v1/house/worker/*` | для GPU-обработчика: взять задачу, скачать пакет, загрузить результат (ключ обработчика, не приложения) |

Хранилище: `data/house-scans/{id}/` на VPS; лимиты: 600 МБ на скан, 6 ГБ всего (env `HOUSE_SCAN_MAX_MB`, `HOUSE_SCANS_TOTAL_GB`). Сейчас свободно 16 ГБ. Пакет удаляется через 7 дней после готового результата.
Пакет едет к GPU по ссылке на скачивание с нашего сервера (Caddy отдаёт файл, Node не участвует).

**Уведомление «Макет готов».** Правильно — пуш APNs с сервера: нужен ключ APNs (.p8) из Apple Developer пользователя. До него — фоновая проверка статуса (`BGAppRefreshTask`) + локальное уведомление; при открытии приложения статус обновляется сразу.

### 1.5 Конвейер на GPU (этап 1b)

Обработчик — Docker-образ, Python 3.11 + CUDA 12. Шаги и время на RTX 4090 / L40S для 350 кадров:

| # | Шаг | Инструмент (лицензия) | ≈ время |
|---|---|---|---|
| 1 | Распаковка, проверка, отбор резких кадров (дисперсия лапласиана) | OpenCV (Apache-2.0) | 0,5 мин |
| 2 | **Глубина**: LiDAR есть — берём её (уверенность ≥ 1); LiDAR нет — монокулярная глубина, приведённая к масштабу ARKit по опорным точкам и контрольному размеру | Depth Anything V2 **Small** (Apache-2.0); большие версии — некоммерческая лицензия, не берём | 1–2 мин |
| 3 | **Сетка с размерами**: TSDF-слияние глубин по позам ARKit (воксель 2 см у дома, 5 см дальше) → меш → упрощение | Open3D `ScalableTSDFVolume` (MIT) | 2–3 мин |
| 4 | Уточнение поз (опц.): ICP кадр-к-сетке, если дрейф ARKit > 5 см на круге | Open3D (MIT) | 1 мин |
| 5 | **Сегментация** кадров: стена / крыша / окно / дверь / земля / растительность / небо; метки проецируются на меш голосованием | Grounded-SAM 2 = Grounding DINO (Apache-2.0) + SAM 2.1 (Apache-2.0); запасной — OneFormer ADE20K (MIT) | 3–5 мин |
| 6 | **Вписывание плоскостей**: RANSAC по классам → стены (вертикальные), скаты (наклонные), отмостка/земля → футпринт дома, высота карниза, конёк, уклоны **по измеренным стенам**; окна/двери — прямоугольники на плоскостях стен | Open3D `segment_plane` + свой код | 1 мин |
| 7 | **Крыша**: тип и детали — Gemini 4 Hydrogen по 4–6 лучшим кадрам «верхнего яруса» (этап 0), геометрия — по шагу 6; невидимые скаты — симметрия + метка `assumption` | OpenRouter | 0,5 мин, ≈$0.04 |
| 8 | **Вид как в жизни**: Gaussian splatting с известными позами (без SfM), регуляризация глубиной, 7 000 итераций | gsplat (Apache-2.0) | 6–10 мин |
| 9 | Упаковка результата: `house.glb` (сетка + цвета по классам), `house.spz` (сплаты, сжатые), `house.json` (параметрический черновик: стены, проёмы, крыша, метки достоверности), превью PNG | trimesh (MIT), spz (MIT) | 0,5 мин |

Итого 15–25 мин ≈ **$0.30–0.60** на 4090/L40S. Рельеф участка (этап 4) добавится шагом 6b: точки класса «земля» → сетка высот 10 см.

**Что не берём:** COLMAP/GLOMAP (позы уже есть из ARKit; оставляем запасным для обычных iPhone при плохом трекинге), MASt3R/DUSt3R (некоммерческие лицензии), Depth Anything V2 Large, Depth Pro (лицензия Apple — только исследования).

### 1.7 Точность

| iPhone | Масштаб | Ожидаемая ошибка размеров дома |
|---|---|---|
| Pro (LiDAR, до ~5 м надёжно) | LiDAR | 1–3 см у стен, 3–8 см на коньке (по геометрии стен) |
| Обычный | ARKit VIO + контрольный размер | 2–5 % без контроля, ~1 % с одним размером |

LiDAR видит ~5 м: стены снимаются с 3–5 м («ближний круг»), крыша — по фото с «дальнего круга» + плоскости стен.

### 1.8 Риски

- Дрейф ARKit на полном круге (30–60 м пути) 5–20 см → шаг 4 (ICP) и замыкание круга по первым кадрам.
- Высокие двухэтажные дома: верх фронтона LiDAR не достаёт → геометрия по фото (этап 0) с привязкой к измеренным стенам.
- Заборы / деревья вплотную → «предположение» на закрытых участках.
- Прямое солнце и снег — хуже LiDAR; подсказка «снимайте в пасмурную погоду или в тени».

### 1.9 Порядок работ этапа 1

1. ✅ Приём пакета на сервере (частями, с докачкой, проверка SHA-256) + тест.
2. ✅ Экран «Скан дома»: интро, камера, кольцо покрытия, подсказки, запись кадров/глубины/поз, упаковка zip, загрузка.
3. ⏳ Выкат серверной части на боевой сервер (ждёт «да» пользователя).
4. ⏳ Первый реальный скан с iPhone Pro → проверка пакета на сервере (позы, глубина, кадры).
5. ⏳ GPU-обработчик: Docker-образ, шаги 1–3, 6, 7, 9 (сетка + размеры + крыша), затем 5 и 8.
6. ⏳ Экран результата (3D-слепок с размерами и метками).
7. ⏳ Пуш APNs (нужен ключ .p8).

## 2. Дополнения (2026-11-25): максимум точности при минимуме затрат

### 2.1 Точность — что сделано в записи скана
| Приём | Что даёт | Цена |
|---|---|---|
| Север по компасу (`gravityAndHeading`) | макет сразу ложится на карту, участок и солнце (±5–10°, точно — по 2 углам участка) | 0 |
| GPS-точка дома (лучшая из 8 с) | поиск участка, привязка к кадастру и тени | 0 |
| Отбраковка смазанных кадров (дисперсия лапласиана < 45 % медианы) | меньше «мыла» в сетке и сплатах | 0 |
| Опорные точки ARKit на каждом кадре (`points/*.bin`) | уточнение поз на GPU (bundle adjustment без SfM) — убирает дрейф круга | 0 |
| Снимки крыши 12 Мп (до 36, раз в 2 с на ярусе «крыша») | ИИ видит кровлю/трубы/водостоки; точки конька триангулируются точнее | 0 |
| Контрольный размер рулеткой | проверка масштаба (с LiDAR) или подгонка (без LiDAR); в отчёте — расхождение в см | 0 |

### 2.2 Точность — что делает обработчик (`gpu-worker/`)
- TSDF-сетка по глубине LiDAR с позами ARKit (воксель 2 см), RANSAC-плоскости, разбиение на связные куски.
- Футпринт по парам противоположных стен (расстояние между плоскостями усредняется по тысячам точек → σ ≈ 1 см).
- Карниз — по верху карнизных стен; **конёк и уклон — по кромкам фронтона** (две прямые по верхней огибающей стены).
  Если LiDAR не достал до верха (> 5 м), прямые продолжаются — метка `extrapolated`.
- **Конёк по фото**: ИИ отмечает конёк на 3–8 кадрах с известными позами → триангуляция (DLT) с отбросом кадров,
  где ИИ промахнулся. Работает на любой высоте и без LiDAR.
- Проверка в CI на синтетическом доме известных размеров (`.github/workflows/house-worker.yml`): допуски
  ширина/длина ±3 см, карниз ±4 см, конёк ±10 см (продолжение кромок), уклон ±1,5°, триангуляция ±5 см.

### 2.3 Участок по кадастру (НСПД Росреестра)
- Запрос идёт **с iPhone** (НСПД отвечает только российским адресам; наш VPS в Нидерландах). Сертификат nspd.gov.ru —
  российский УЦ Минцифры: в приложение встроен корень Russian Trusted Root CA (SHA-256 D26D…CF31), доверие **только для nspd.gov.ru**.
- Поиск: по кадастровому номеру (`/api/geoportal/v2/search/geoportal`) или «Я на участке» по GPS (WMS GetFeatureInfo, слой 36048).
- Показываем: граница на спутниковой карте, площадь по ЕГРН и по контуру (расхождение > 2 % — предупреждение), категория, ВРИ, кадастровая стоимость.
- Проверки: ВРИ допускает жилой дом; земли сельхозназначения; отступы дома ≥ 3 м и построек ≥ 1 м от границы (СП 30-102-99 п. 5.3.4, СП 53.13330.2019 п. 6.7);
  выход за границу; процент застройки (ПЗЗ, по умолчанию 30 % с пометкой «уточните»); напоминание о пожарных разрывах (СП 4.13130.2013).
- Участок уходит в пакет скана (`manifest.parcel`) — макет и будущие постройки проверяются по границе автоматически.
- ⚠️ Адреса API НСПД не проверены из России (с нашего VPS недоступны) — первая проверка на телефоне пользователя.

### 2.4 Экономия
- GPU: RunPod Serverless 4090 посекундно — платим только 15–25 мин работы; образ один для RunPod и immers.cloud.
- ИИ: только Gemini 4 Hydrogen по 4–8 лучшим кадрам крыши (≈ $0.03–0.05); геометрия — код, не ИИ.
- Кадастр — бесплатно (публичная карта), запрос с телефона, сервер не нагружается.
- Сервер VPS: апгрейд до vCS-4 (2 vCPU / 4 ГБ / 80 ГБ, 28 €/мес) — память сейчас исчерпана (swap 1,9/2 ГБ), процессор почти свободен.
